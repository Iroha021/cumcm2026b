# 第四问：最终思路与流程算法

> 队伍 YOUR_TEAM_ID。程序：`python run.py live --scenario q4`（与第三问同一程序，仅 `--scenario` 切换）。
> 本文档描述**最终采纳**的算法与其依据；被否决的方案见第 6 节（含量化理由），避免重复试错。

## 1. 问题的三个结构性事实（全部可证明，算法建立其上）

**事实 1（有界条带）**：若某频道在 P₁ 处测到示向度 θ₁，则源必满足 `|S−P₁| ≤ R ≤ 1500 m`。
于是源不在"无界射线"上，而被截断在一条**有界细长条**内：长 ≤ 1500 m，横向宽
≤ `2·1500·tan 1° ≈ 52 m`（±1° 是位置相关的**固定偏差**，不是随机噪声，重复测量无增益）。
→ 单条示向度即可支撑"沿条带逼近清除"，不必等第二条示向度。

**事实 2（盲区 = 过源点的固定半平面）**：定向源覆盖 180°，α 未知且固定。设某频道全部探测点
相对源的最大角间隙为 `G`：
- `G ≥ 180°` ⇒ 存在一个半平面能装下**全部**探测点 ⇒ 它们**可能全在盲区**（这解释了一类
  反常现象：源的最近探测点仅 500 m ≪ R，却从未被测到——距离从来不是问题）；
- `G < 180°` ⇒ 任何半平面都必含某个探测点 ⇒ **只要距离 ≤ R 就必被测到**。
→ `G` 是"探测是否已被保证"的可判定量，既可作为测量点的筛选判据，也是缺席判定的前提。

**事实 3（清除半径与覆盖角无关）**：`/clear` 只要求 20 m 内，与覆盖半平面无关。
→ 定位阶段的盲区困难不传染到清除阶段；这是"条带扫掠"能成立的关键。

## 2. 总体流程（滚动巡游 + 节点化决策）

每一步只做一次 HTTP 动作，动作后立刻用观测更新后验并**重规划**（滚动时域）：

```
初始化：World(20 频道，各频道一个粒子云) / CostModel(5 m/s, 5 s 测量, 1 s 换频) / 覆盖站点集合

while 预算未尽:
    Action = Policy.decide()
    if Action 为 None: break
    观测 = SimClient.post(Action)            # /measure 或 /clear
    World.observe(观测)                       # 三态似然 + α 后验 + 存在性检验
    CostModel.update(观测)                    # 虚拟时间与位置镜像
```

`Policy.decide()` 的优先级（越靠前越优先，命中即返回）：

```
1  near 直清：若 /measure 返回 near（≤5 m 且处于覆盖角内）→ 立即 /clear
2  就地补扫：清除未命中后，若新的最佳清除点离当前位置很近 → 就地连续清除
              （否则把它塞回巡游队列会被 TSP 排到别的站点之后，一次 40 m 变成几百米转场）
3  就地清除：当前站点上仍可清除的目标 → /clear
4  批量测量：当前站点未测完的频道 → /measure
5  节点选择：重规划节点集 → TSP 排序 → 取价值最高的一个
```

节点集由 `TourPlanner.build_nodes()` 生成，四类节点按价值竞争：

| 节点 | 价值 | 说明 |
|---|---|---|
| `clear` | `v_clear · P(一次成功)` | 已定位（区域直径 ≤ 20 m）或**单示向度条带扫掠** |
| `sweep` | `v_sweep · Σ(该站最值得测的频道价值)` | 覆盖巡游站点（贪心覆盖，`r=1200 m`，7 站） |
| `advance/extra` | `v_sweep · 站点价值` | 专程补测点（问题二第二点 / GDOP 补点） |
| `verify` | `v_verify` | 收尾复核被判"无源"的频道 |

## 3. 第四问专属的五条机制（全部 `mode == "q4"` 门控，除第 5 条）

**M1 覆盖概率门控（档 1.0）**：用 α 后验计算候选站点落在覆盖半平面内的概率
`p_cov`，`p_cov ≤ 1e-3` 的站点不再为该频道排序，避免往盲侧白测。

**M2 张角增益门槛（档 3.0，实测 +1.3 pp）**：只有当测量点能把最大角间隙压缩
`≥ gap_gain_deg (10°)` 时才为该频道排序（已测 `≥ 3` 次起生效）。
依据是事实 2：不能压缩间隙的测量点必然是同侧白测——诊断显示 B 类频道 32/37 只有
1 条示向度却已测 16–20 次（= 上限），测量预算被整段烧光。

**M3 有界条带扫掠清除（档 4.0，实测 +1.9 pp）**：`_clear_candidates` 对"只有 1 条示向度
且已测 ≥ 8 次"的频道放开 `len(bearings) < 2` 门槛，依据事实 1 + 事实 3 沿条带直接扫掠。
每次未命中都以 `|S−P| > 20 m` 收缩后验并排除该点，**下一次尝试自动沿条带前移**
（有信息，不是原地重试）。

**M4 累计把握排序（档 4.0）**：条带扫掠节点的价值用
`1 − (1 − p_succ)^剩余次数`，而非单次 `p_succ`。否则 `p_succ ≈ 0.02–0.04` 的节点
永远排在 `sweep` 之后而永不执行——这正是 B 类 28 个源里 **19 个从未尝试过清除**的原因。

**M5 缺席判定的 (1/2)^m 折扣（档 1.0）**：Q4 中"静默"不能证明无源（可能是盲区），
故静默证据按 `(1/2)^m` 折扣而非硬约束。文献标定：`P(静默|有源) ≤ 1/2` ⇒ 要虚警率
`ε=10⁻³` 需 `m ≥ 10` 次静默；现有 `min_probes_before_absent = 8` 对应 `ε ≈ 4×10⁻³`，量级一致。

## 6. 被否决的方案（含量化理由，不再重试）

| 方案 | 结果 | 否决理由 |
|---|---|---|
| 沿示向射线**直着**前进补测（档 1.1） | 0.7756 | 与源严格共线 ⇒ 交会角 0°、GDOP=∞，第二条方位零价值；半平面是凸集 ⇒ "无信号⇒遮挡"永不触发（实测 0/1/0 次） |
| 偏转 50° 前进（档 1.1'） | 0.5033 | 交会角 37° 但两方位近平行，定位区域被拉成长条；13/20 局撞动作上限（vt 16380 s） |
| 专程"包夹"补测点（档 2） | 0.7153 | 让未测到频道继续占预算 ⇒ 延长扫掠、推后清除；全向源 95.5%→89.0% |
| 零行程包夹（只加进批量） | 0.6587 | 同上，"从未测到"从 0 升到 24，最近探测距离 509→1308 m |
| 第二点换边 ±120°/±150°（档 3D） | 0.7934 | 换边逃出盲区但交会几何太差，区域仍清不掉，且多付 357 s |
| 对"从未测到"频道加张角门槛（档 5） | 0.5462 | 判据前提失效：探测点可能只是**距离太远**，却污染代理源位置；频道被饿死 ⇒ 巡游 3085 s 提前结束，全向源掉到 70.1% |

**两条通用教训**：① 任何让"未测到频道"继续占据价值/预算的改动，都会延长扫掠、推后清除，
代价高于收益；② 对"从未测到"的频道限制测量必定有害，覆盖率只能靠**空间铺开**。

## 8. 风险与待办

1. **官方时钟口径未复测**：影子模拟器的"虚拟时间"（约 4500–5400 s）是自身计费模型，
   与官方 `/measure` 返回的 `remaining_real_duration_s ∈ [0,1200]`（20 min 程序实时预算）
   及 25 min 窗口的换算关系**必须用一次官方 `live` 演练实测**（影子约 5000:1 压缩比，
   不能直接外推）。这是当前最大的未知量。
2. 正式测试仅 3 次，须先演练对齐 `robot_id`（= 队号）、日志大小（< 2 MB）与导出。
3. 参数 `clear_max_attempts_stuck`、`clear_min_success_prob_stuck` 继续放宽仍可能提升
   清除比例，但虚拟时间同步上升；是否继续取决于第 1 条结论（若时间宽裕可再放宽）。
4. C 类（定向源 13.1% 从未测到）只剩**空间手段**可选（加密站点，文献给出的三角站环
   边长 `l ≤ (√3/2)·R_min ≈ 866 m`）；现有 7 站点最差边缘覆盖 963 m 已达标，加密会显著
   增加行程，需实测权衡后再定。
